# web source type: URL-backed sources, flavored by hosting family

Several doc sites worth indexing are hosted on ReadTheDocs but their projects
build no PDF. Exhibit A: `docs.ansible.com/projects/ansible/latest/index.html`
— verified 2026-08-30 to return 403/404 at every RTD download endpoint (the
custom-domain path and the readthedocs.org path). The two existing ingest
paths don't fit: there is no PDF to drop into a `dir` source, and a full docs
repo clone via `git_repo` is heavy. These docs are unindexable.

The failure mode to design against is not unindexed — it is *silently unindexed
while looking indexed*. rtfm is an agent-facing tool: a declared source that
contributes nothing must be visible as such in every search response, or an
agent will answer confidently from a corpus that doesn't contain the docs.

## Decisions

### Type name: `web`, flavored by hosting family

`type = "web"` plus `flavor = "readthedocs"` for the first flavor. ADR 0002
types sources by sync method; the web sync method (re-fetch) is shared by all
flavors. A flavor defines the three things that genuinely differ between
hosting families: page discovery, version-to-URL mapping, and content
extraction. `readthedocs` covers sites generated by ReadTheDocs, on
readthedocs.io subdomains or custom domains (`docs.ansible.com/projects/
ansible/latest/...`, `{slug}.readthedocs.io/en/{version}/...`,
`{domain}/en/{version}/...`). Unknown flavors are refused at load; the URL
itself is never shape-gated.

### `url`-only identity, trusted

The entry holds the index page URL, exactly as copied from a browser. There
is no load-time shape gate: the flavor trusts the URL, attempts the parse, and
failure is per-source index state, never a load-time refusal. The version
lives in the URL (`latest` is mutable, `stable` and `v2.18` are pinned).
`mutable` is not applicable — a fetch cache has nothing for the user to edit.

### Explicit-reindex staleness — search never fetches for web

`search` never fetches for web sources (the refresh loop is dir/git_repo
only). A web staleness *check* is itself a network fetch, and the query path
must not do network I/O. `reindex` fetches; `status` reports facts from
`web_meta` (tracked version, page count, fetched-at, upstream lastmod) with no
probing. This amends ADR 0003's every-query staleness model for web sources.

### Discovery: index-page nav crawl, llms.txt fast path

Empirical findings from live probes (2026-08-30) shaped this:

- **There is no per-page sitemap on real RTD hosts.** The domain-root
  `sitemap.xml` is a *version index* — one `<url>` per public version with
  `lastmod` (requests.readthedocs.io: exactly two entries, latest and stable).
  Per-version sitemap paths (`/en/latest/sitemap.xml`,
  `/projects/ansible/latest/sitemap.xml`) all 404, despite RTD's own docs'
  robots.txt example showing `/en/stable/sitemap.xml`.
- **`llms.txt` is opt-in per project** (404 on all probes) — a fast path when
  present, never the primary.
- **`_sources/` raw RST is 404'd** by RTD — rendered HTML is the only content
  source.

So discovery harvests links from the index page (the RTD sidebar carries the
full toctree), filtered to the same version root and excluding artifacts
(`search.html`, `genindex.html`, `_static/`, `_sources/`, cross-version and
cross-host links). If `{version}/llms.txt` parses, its link list replaces the
crawl. A hard page cap (`RTFM_WEB_MAX_PAGES`, default 2000) bounds reindex
time; truncation is an honest `TRUNCATED (N/M)` state, not a silent cut.

### Extraction: `div[role="main"]`, stdlib only

`.html` joins `TEXT_EXTS` for ALL sources (extension-based handling, ADR
0002). Extraction uses stdlib `html.parser`: the `div[role="main"]` region
only (nav, footer, search, breadcrumbs dropped), code inside `<pre>` verbatim,
`<script>`/`<style>` dropped, h1–h3 into the doc-level signal (ADR 0012),
title = first h1. No new runtime dependency — the PEP-723 block is unchanged.
The locator is line numbers in the *extracted* text under the cache-relative
path; `read` re-extracts, so hit locators and reads stay consistent. The
page's public URL is derivable (the source's index `url` up to its last `/`,
plus `relpath`) — the skill documents the derivation, so no URL column in the
index.

### Cache + incremental reindex

Fetched pages are cached as raw HTML at `~/.rtfm/web/<name>/`, mirroring the
URL tree under the version root. Reindex hands the cache to the shared
`_index_files` core: the content-addressed store dedups on file bytes, so an
unchanged page costs nothing at extract time — refetch-all with cheap dedup,
the same model as git_repo's full-checkout-then-diff. Cache files no longer in
the page set are purged; on failure the prior cache and index rows are left
untouched, so prior content stays searchable.

### Skip-optimization: the version-index lastmod

Before crawling, reindex GETs the domain-root `sitemap.xml` and reads the
tracked version's `lastmod`. If the previous run *completed* (status `ok` or
`truncated`) and lastmod is unchanged, reindex reports "up to date" and skips
the crawl — on a 20-minute site this makes reindex a casual call. The
optimization is conservative: a CDN-lagged lastmod re-crawls, and an
unparseable sitemap (custom sitemaps exist) always crawls. A truncated or
failed run never skips.

### Cooperative-only; bot walls are a classified state

Web sources are best-effort and cooperative (CONTEXT.md): no OCR, no JS
execution. A host that walls off scripted fetching — Cloudflare's "Just a
moment..." challenge, detected by `cf_chl`/`challenge-platform` markers in a
403/429 body — yields `ERROR:BLOCKED:`. docs.ansible.com is a documented
known-blocked case (verified 2026-08-30: the challenge arrives even with a
real browser UA); the documented alternative for that host is a `git_repo`
source on the docs' source repo. Browser escalation (an opt-in "try harder"
mode) is roadmap-only — ROADMAP.md.

### Failure classes and the agent contract

Five failure classes, message-style consistent with git_repo's classified
errors: `ERROR:BLOCKED:`, `ERROR:RATE_LIMITED:`, `ERROR:FETCH_FAILED:`,
`ERROR:NOT_READTHEDOCS:` (the trust-the-URL case: the page fetched but has no
`div[role="main"]`), and `TRUNCATED (N/M)` (a warning state, not a failure).

Agent-facing contract — a declared-but-failed source must not look covered:

- `search` responses carry `sources_failed` listing web sources with no
  indexed content (state strings: "never indexed" or "last index FAILED:
  <class>"); indexed web sources appear in `sources_searched` like any other.
  A web source whose *latest* reindex failed but whose prior content is still
  served warns loudly per search (`!!! SOURCE FAILED 'x' !!! ... serving
  previously indexed content`), the same shape as git_repo's AUTO-REINDEX
  FAILED.
- `list_sources` reports `web_status`: `never indexed` / `indexed` /
  `TRUNCATED (N/M)` / `last index FAILED: <class>`, plus the tracked version,
  page count, fetched-at, and upstream lastmod.
- The bundled `read-the-manual` skill tells the agent what a failed source
  means: not part of the corpus; attempt one reindex, then state the gap.

### `web_meta` table; schema 4 → 5

A new `web_meta(source TEXT PRIMARY KEY, url, version, fetched_at, page_count,
total_pages, lastmod, status, error)` table holds per-source web state —
separate from `source_meta` (git state) rather than widening it with NULL
columns. Same migration strategy as ADR 0013: drop all tables, rebuild empty;
the index is a cache. Zero backward-compatibility concerns.

## Consequences

- `search`, `reindex`, `list_sources`, and `read` gain web awareness;
  `_stale_delta` stays dir/git_repo-only (web never auto-refreshes on search).
- `.html` files in *any* source (including plain `dir` sources) are now
  indexable — the shared extension-based handling makes HTML extraction a
  general capability, not a web-only one.
- The `Source` dataclass gains `flavor`; `url` becomes operational for a
  third type.
- One new table, one schema bump; the index is a cache, so no migration path
  is owed.
- RTD's real-world structure (no per-page sitemap, opt-in llms.txt, dead
  `_sources`) is recorded here so the nav-crawl design is not re-litigated.
